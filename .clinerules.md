# Project Rules for AI Assistants

Test station for reusable VEDA GitHub Actions + Projects-v2 seeds. See `CLAUDE.md` (full guide) and
`docs/DECISIONS.md` (rationale). This file = the must-follow rules/gotchas only.

## Rules
- **Generators: stdlib-only Python 3.12 + `gh` CLI subprocess.** No `requests` / pip deps. Reuse the
  retrying `gh()`/`gh_json()`/`gh_graphql()` wrappers (pattern in `seed/setup_project.py:25-43`).
- **Two composite actions:** root `action.yml` (FTE) and `pr-finder/` (PR Finder). Keep them independent;
  don't merge. A second/Nth action = its own subfolder.
- **Board reads need a `repo+read:org+project` token** (`PROJECT_TOKEN_FOR_BOARD_READS`), never the
  default `GITHUB_TOKEN`.
- **Objective = issue title contains "objective"** (case-insensitive) — don't change this without
  updating both generators.
- **Deterministic output ordering** (sort objectives/issues/PRs) so report diffs stay clean.
- **One Netlify site per dashboard** via base dir + a `netlify.toml` inside that dir; don't put a second
  build in the root `netlify.toml`.
- **Theming = CSS vars + `data-theme` on `<html>`** (`:root` light, `:root[data-theme="dark"]` override);
  default **dark**, persisted per-app in `localStorage` (`fte-/leave-/pr-theme`). Only chrome adapts —
  **never invert data colors** (person/status palettes, USWDS PR tags). For pr-dashboard, keep the dark
  CSS in `pr-finder/generate_pr_finder.py` and `pr-dashboard/pr_finder_all.html` **in sync**.

## Gotchas
- `subIssues` GraphQL works with **no** `GraphQL-Features` header; the `addSubIssue` mutation may not —
  the seeder falls back to REST (which needs the child's **`databaseId`**, not node id).
- Closing PRs use `closedByPullRequestsReferences(includeClosedPrs: true)` — closing links only, not
  cross-references.
- Seeding issues into a repo whose FTE action has `on: issues:` enabled floods that repo's Actions tab.
  This repo keeps that trigger commented out on purpose.
- Merging seed PRs can be blocked by base-branch policy → left OPEN (not an error).
- **Shared checkout:** `git commit` lands on whatever branch HEAD is on — verify the branch before
  committing when multiple sessions share the working tree.
