# Project Rules for AI Assistants

Test station for reusable VEDA GitHub Actions + Projects-v2 seeds. See `CLAUDE.md` (full guide) and
`docs/DECISIONS.md` (rationale). This file = the must-follow rules/gotchas only.

## Rules
- **Generators: stdlib-only Python 3.12 + `gh` CLI subprocess.** No `requests` / pip deps. Reuse the
  retrying `gh()`/`gh_json()`/`gh_graphql()` wrappers (pattern in `seed/setup_project.py:25-43`).
- **Three composite actions:** root `action.yml` (FTE), `pr-finder/`, `leave/`. Keep them independent;
  don't merge. A second/Nth action = its own subfolder.
- **Board reads need a `repo+read:org+project` token** (`PROJECT_TOKEN_FOR_BOARD_READS`), never the
  default `GITHUB_TOKEN`.
- **Objective = issue title contains "objective"** (case-insensitive) — don't change this without
  updating both generators.
- **Deterministic output ordering** (sort objectives/issues/PRs) so report diffs stay clean.
- **One Netlify site per dashboard** via base dir + a `netlify.toml` inside that dir; don't put a second
  build in the root `netlify.toml`.
- **`dse-hub/` (4th site) has NO generator** — hand-entered JSON. Source of truth = canonical
  `dse-hub/data/{meetings,pis}.json` arrays; adds/edits stage in the in-app **Changes cart** → one
  prefilled new-file PR creating `dse-hub/data/changes/<ts>.json`, merged over the canonical arrays at load
  (upsert by id, newest `ts` wins). **Don't reintroduce one-file-per-record.** `dse-hub/scripts/compact.mjs`
  + its workflow fold changes in. Details in `docs/DSE_HUB.md`.
- **`algorithm-catalog/` (6th site) has NO generator** — hand-curated `data/{algorithms,events,hazards}.json`,
  submissions stage in a cart → one prefilled new-file PR under `data/requests/`, folded into
  `data/requests.json` by `scripts/compact.mjs`. Same shape as dse-hub. Details in `docs/ALGORITHM_CATALOG.md`.
- **The catalog's standard lives in ONE place and is mirrored, not re-derived.** `algorithm-catalog/src/rules.ts`
  is the source; `scripts/validate_data.py` mirrors it 1:1; `scripts/rules_parity_test.py` fails if they
  drift (it also fails on a **new exported const** the Python doesn't know). Change a rule → change both,
  then run both scripts. CI runs them on every PR touching `algorithm-catalog/**`.
- **STAC event name = `YYYYMM_Hazard_Location`, EXACTLY 2 underscores** — `^[0-9]{4}(0[1-9]|1[0-2])_[^_]+_[^_]+$`.
  This is **deliberately stricter than upstream** `dps/_validate.sh` (whose trailing `.+` lets the location
  slot swallow extras). Multi-word hazards AND locations are CamelCase (`TropicalCyclone`, `GulfOfMexico`).
  Serialize hazard **ids** (= the CamelCase tokens), never display labels.
- **Products carry two hazard lists.** `hazards` = broad, drives discovery/filtering; `primaryHazards` =
  sparse subset, drives the Submit form's auto-selection. Keep `primaryHazards ⊆ hazards` (validator
  enforces it) and keep it *sparse* — widening it dumps dozens of chips on the user.
- **`board-explorer/` (7th site) DOES have a generator** — unlike dse-hub/algorithm-catalog. It mirrors a
  Projects v2 board to the `board-explorer/data` branch (6-hourly workflow), and the SPA fetches that at
  runtime with `public/data/` as the fallback. **Never put a board token in the browser** — that was the
  rejected alternative; see `docs/DECISIONS.md`.
- **`app-catalog/` (8th site) is Astro 5 + Pagefind + MDX, NOT Vite+React** — the only such app here, on
  purpose: it's a content catalog, not a data dashboard. One entry = one MDX file in
  `src/content/catalog/`; `src/content.config.ts` is the single source of truth for fields.
  **`limitations` (min 1) AND `solves` are REQUIRED** — `astro build` fails without them, so the rules
  "every entry says what it costs you and what it removes" are gated, not reviewed. Don't relax them.
  Details in `docs/APP_CATALOG.md`.
- **In `app-catalog/`, MDX parses markdown INSIDE inline SVG** — a leading-space `_` opens emphasis and
  `[^x]` reads as a footnote ref, silently truncating the rest of the `<svg>` with no error. Wrap such
  text in `{"string literals"}`. Verify with `grep -c '<text'` on the source vs the built HTML.
- **Astro scopes component styles** — a rule in one component targeting another component's elements
  silently does nothing (`[data-entry].is-hidden` lost to EntryCard's `.card{display:flex}`, so the type
  filter set classes but hid nothing). Cross-component rules go in `src/styles/global.css`. **Assert
  computed `display`/`opacity` in tests, never just the class.**
- **The board export uses raw ProjectV2 GraphQL, NOT `gh project item-list`.** The CLI's flattened output
  is simpler and is right for the FTE/PR-Finder generators, but it exposes **no** state, `merged`, label
  colours, avatars, milestone, timestamps or sub-issue progress — most of what this app renders. Don't
  "simplify" it back to the CLI.
- **Board fields are DISCOVERED, never hardcoded** — whatever `fields(first:60)` returns drives both the
  export and the UI's pickers, so adding a board column needs no code change. Only author-defined types
  survive (`text/number/date/single_select/iteration`); GitHub's built-in columns (Assignees, Labels,
  Milestone, Repository, Sub-issues progress, Created/Updated/Closed) are **dropped** from `fields[]`
  because their values ride on `content` and are already top-level item keys — keeping them would give
  the UI a second, permanently empty picker for each.
- **Draftness is a FLAG, not a state.** `state` is `open|closed|merged`; a draft PR is still an *open* PR
  on GitHub, so folding draft into the state enum would make `is:open` skip it.
- **Board Explorer: ONE query string is the source of truth** — pickers, quick pills and chips all read
  their state out of the parsed query and write changes back into it. This is a **deliberate departure**
  from `algorithm-catalog/src/filters/filter.ts` ("start fully selected; a facet narrows only as a strict
  subset"), which suits 10 hazards but not 33 sprints / 23 labels / 22 people, and cannot round-trip with
  a grammar where `label:bug` already means "only bug". **Don't "restore consistency" by reverting it.**
- **Comma = OR, a repeated qualifier = AND** (GitHub's semantics). Each token becomes its own group and a
  match needs a hit in **every** group. **Don't flatten `Facet.include` to a single list** — that silently
  turns `is:open is:closed` from "nothing" (a contradiction) into "everything". Pinned by the e2e suite.
- **Theming = CSS vars + `data-theme` on `<html>`** (`:root` light, `:root[data-theme="dark"]` override);
  default **dark**, persisted per-app in `localStorage` (`fte-/leave-/pr-/board-theme`). Only chrome adapts —
  **never invert data colors** (person/status palettes, USWDS PR tags, GitHub label hexes). For pr-dashboard,
  keep the dark CSS in `pr-finder/generate_pr_finder.py` and `pr-dashboard/pr_finder_all.html` **in sync**.
  **Refinement (board-explorer):** a raw GitHub label hex is often illegible on the opposite background, so
  a chip holds its **hue** fixed (that is the data) and adapts only its **lightness**, by mixing the text
  toward `var(--ink)`. Hue fixed, lightness free — not a licence to re-map data colours.

## Gotchas
- `subIssues` GraphQL works with **no** `GraphQL-Features` header; the `addSubIssue` mutation may not —
  the seeder falls back to REST (which needs the child's **`databaseId`**, not node id).
- Closing PRs use `closedByPullRequestsReferences(includeClosedPrs: true)` — closing links only, not
  cross-references.
- Seeding issues into a repo whose FTE action has `on: issues:` enabled floods that repo's Actions tab.
  This repo keeps that trigger commented out on purpose.
- Merging seed PRs can be blocked by base-branch policy → left OPEN (not an error).
- **Shared checkout:** `git commit` lands on whatever branch HEAD is on — verify the branch before
  committing when multiple sessions share the working tree.
- **Root `.gitignore` ignores `*.json`** → `git add <dir>` silently skips `package.json` / `tsconfig*.json`
  / data JSON; **`git add -f`** them (dse-hub + leave-dashboard both rely on this). **Exception:**
  `algorithm-catalog/` and `board-explorer/` have explicit `!` negation lines, so a plain `git add` works
  there — prefer that route for new apps.
- **`git check-ignore` misleads TWICE, in different ways.** Plain `git check-ignore` lies about
  already-tracked files. And even `--no-index -v` **exits 0 whenever any rule matches — including a
  negation rule** — so an exit-status test reports a correctly re-included file as "IGNORED". Read the
  **rule it prints**: a leading `!` means the file is included. The only unambiguous check is
  `git add --dry-run <dir>` and looking for the file in the output.
- **Reading a Projects v2 board locally needs `read:project`** — `gh auth refresh -h github.com -s read:project`.
  Without it every field of the query comes back `INSUFFICIENT_SCOPES`, including `projectV2` itself.
- **The board crawl gets secondary-rate-limited** (408 items × a deep query over 9 pages). `gh_graphql()`
  backs off and retries, so a full run takes ~70 s rather than failing. Don't "fix" the slowness.
- **`board-explorer/src/csv.ts` imports `./filter.ts` WITH the extension, on purpose.** It is the only
  runtime cross-module import Node reaches when running `scripts/test_search.ts`; every other one is
  `import type`, which erases. Node's ESM resolver needs the extension, Vite doesn't care. Dropping it
  breaks the test suite while the build stays green.
- **Netlify "Deploy Preview canceled" on a PR is usually CORRECT.** Sites with a base directory get an
  implicit skip when the PR touched nothing under that dir — so a README/docs-only PR cancels the preview
  on all eight sites. This happens with or without an `ignore` filter in `netlify.toml`, so omitting `ignore`
  does **not** mean "build on every push". Check `git diff --name-only main... -- <app>/` before suspecting
  Netlify settings.
- **A blank Netlify base directory fails SILENTLY, not with "base directory not found".** Netlify looks for
  `netlify.toml` at the repo root, finds none (by design), logs `Detected 0 framework(s)` /
  `Starting to deploy site from '/'`, uploads the raw repo, and reports a **green** deploy that 404s. The
  tell is `from '/'` in the deploy log. Set base dir in the UI and leave build command + publish dir EMPTY.
